2. CURRENT DESIGN SYSTEM (since 2026-08-06 site-wide redesign)
------------------------------------------------------------------
The whole site was re-skinned in one pass 2026-08-06, promoting an approved
`/home-test` A/B variant to be the site's one design language (that route no
longer exists — it was promoted, not kept as a separate page).

Palette (Tailwind v4 @theme tokens, app/globals.css):
  --color-ht-purple  #2e1848   dark sections, footer, PageHero band
  --color-ht-orange  #fe431a   primary actions / CTAs
  --color-ht-pink    #fe9dd2   accents, card rings
  --color-ht-crimson #ac3026   shadow depth under orange
  --color-ht-cream   #fbf7ec   base page background
Radii: --radius-block 40px, --radius-card 24px, --radius-pill 999px
Fonts: Clash Display Bold (`font-ht-display` — headings/buttons/labels only)
  + Inter (`font-ht-body` — body copy). Loaded once in app/layout.tsx.

Motion: GSAP + Lenis smooth-scroll is the primary system sitewide, in
`components/motion-gsap/*`:
  RevealSection / RevealStagger  — scroll-triggered fade+rise entrances
  SplitWords                     — word-by-word headline reveal
  MagneticButton                 — cursor-follow drift on buttons/links
  HoverCard / HoverCardImage     — card lift + independent image drift
All of these gate on `gsap.matchMedia("(prefers-reduced-motion: no-preference)")`
— under reduced motion, elements simply render at their natural DOM state
(no opacity:0 stuck on screen), by construction. Framer Motion
(`framer-motion`) survives only for `components/motion/RotatingWords.tsx`
(the Hero's specialty-word cycler) — deliberately kept small/self-contained.

Recurring visual conventions worth knowing before touching any page:
  - "Hard-shadow" card: `rounded-card ring-2 ring-ht-pink
    shadow-[0_14px_0_0_var(--color-ht-pink)]` (colour varies by surface —
    purple ring/shadow on light cards, pink on white cards, etc.)
  - Every inner page opens on a dark ht-purple band
    (`components/PageHero.tsx`) — load-bearing, because `Nav.tsx` is
    `fixed` + transparent-until-scroll and needs a dark surface under it for
    contrast. Do not build a new page that skips PageHero.
  - CloudDivider scallop pattern for section transitions into the Footer;
    whatever section sits directly above `<Footer>` needs `pb-[24vw]`
    reserved so the divider's circles don't collide with card shadows.
  - `min-w-0` is required on every `grid lg:grid-cols-N` column that holds
    long-form/constrained-width text, or CSS Grid's default min-content
    sizing silently breaks the layout at narrow widths. This bit multiple
    pages during the redesign; check for it if a grid column looks wrong.
  - Nav/Footer are global (`components/Nav.tsx`, `components/Footer.tsx`),
    same on every route — no per-page nav/footer swapping.

Hard rules carried over from before the redesign, still in force: no
fabricated stats/quotes/logos/reviews; no em dashes in user-facing copy
(code comments are exempt); founder never named on the site; "X, not just
Y" is deliberate brand voice, not an AI tell — do not "fix" it.

GOTCHA HIT AND ROOT-CAUSED THIS SESSION (worth knowing for any future
visual-verification work on this site): `take_screenshot` with
`fullPage: true` can render entire below-the-fold sections as blank/missing
on this site, even though the content is real and correctly sized in the
DOM. Cause: fullPage screenshots instantly resize the viewport to full
document height instead of scrolling through it, and this site's GSAP
ScrollTrigger reveals (RevealSection/RevealStagger) never receive the
normal scroll events that would fire their reveal tween, so they stay stuck
at their initial `gsap.set(el, {opacity: 0, ...})` state. FIX: scroll to a
specific position via `evaluate_script` + `window.scrollTo`, then take a
non-fullPage (viewport) screenshot at that position instead. Do not
diagnose a "content vanished" fullPage screenshot as a real bug on this
codebase before checking with a normal scroll first.

§16 — Sitewide scroll-stuck-halfway bug fix (2026-08-11, commit fb5e268)

Johandre reported he could only scroll about halfway down every page before
it stopped. Confirmed live on production: document.documentElement.scrollHeight
was 8900 but window.scrollTo(0, 8000) only settled around scrollY 5026.

Root cause: components/motion-gsap/LenisProvider.tsx creates a Lenis
instance with default autoResize: true, which watches
document.documentElement via a ResizeObserver. That observer does not fire
when page content grows the document's scrollHeight without the <html>
element's own box size changing (confirmed by reading
node_modules/lenis/dist/lenis.mjs directly). Lenis's cached scroll limit
falls behind the page's real height as content loads/expands, so scrolling
silently caps out partway down every page.

Fix: resync Lenis to GSAP ScrollTrigger's own "refresh" event (reliable —
re-measures on window load/resize and whenever any ScrollTrigger instance
changes) instead of relying on Lenis's own ResizeObserver alone. Added a
named handleResize function calling lenis.resize(), wired to
ScrollTrigger.addEventListener("refresh", handleResize) and
window.addEventListener("load", handleResize), with matching
removeEventListener calls in the useEffect cleanup (named references
required — inline arrows in both add/remove would silently fail to
unregister).

Verified via a local production build (npx next build && next start) using
Chrome DevTools MCP: scrolled both / and /pricing to their computed max
(scrollHeight - innerHeight) and confirmed scrollY settles at the target
on both. Note for future verification: Lenis intercepts window.scrollTo()
and animates toward the target over several rAF ticks rather than jumping
instantly, so a short polling-stability window (a few hundred ms) can
falsely report "stuck" while Lenis is still spinning up, especially on
heavier pages. Use a stability window of at least 1-2 seconds when
scripting this kind of check again.

npx tsc --noEmit and npx next build both clean before commit. Pushed to
main immediately after (fb5e268) — Vercel deploy should be live within a
few minutes of the push.
